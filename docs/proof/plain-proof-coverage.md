# Plain proof rule for repositories outside selection

On a machine in selected mode, the owner can now list other repositories in `~/.config/spec-lock/plain`. A plain rollout registers their two hooks in each repository's common config with `--plain`. From then on, code that lands on their main branch needs a proof that names a committed spec and every one of its AC ids, with no evidence manifest. The central file, the selected policy id and the selected repository's registration are never written. This is a local candidate: nothing was pushed, and no real owner file, hook registration or installed copy was touched.

Why it was needed: the earlier switch-on plan used global hooks with opt-outs. On a machine already in selected mode, `spec-lock-rollout activate` refuses that plan with `legacy activation cannot replace selected registration`. In every unselected repository, `spec-lock check` printed `unselected, not checked` and then `spec-lock: ok` for code without a proof. [Scratch probe of both](https://assets.agee.dev/evidence/spec-lock/a528cb0d156f6a36aba8ad99c4a573d2/selected-mode-probe.sh).

## Known limits

- Plain coverage needs a selected central file. A machine with no selected repository cannot use it.
- Activation compares entries by their exact path text. An owner entry for the same repository spelled another way reads as a difference and refuses.
- A plain registration whose line the owner removed by hand stays registered until its two hooks are unset, as the README says. `doctor` reports it, and its hook command still runs the installed checker, so that install must stay in place.
- The fix for paths that are not UTF-8 is tested through the file's bytes. No repository at such a path was created, because this Mac refuses those names.
- Nothing here enrolls a repository on GitHub. The GitHub action's runner has no owner files.
